# Sponsor findings: Tempo Stablecoin DEX on Moderato testnet

Observed directly against `https://rpc.moderato.tempo.xyz` (chain 42431) with `viem@2.57.4` (`viem/tempo`, `ox@0.14.54`). Every row below came from a real RPC call or transaction made from this repo. Nothing is copied from the February TempoVault spec.

| Finding | How it was observed | Product consequence |
|---|---|---|
| DEX precompile lives at `0xdec0000000000000000000000000000000000000` | `Addresses.stablecoinDex` in viem, all calls in `scripts/live-slice.ts` succeed against it | Single canonical address, no deployment of our own |
| `MIN_ORDER_AMOUNT` is `100_000_000` (100 tokens at 6 decimals) | `readContract MIN_ORDER_AMOUNT` | Mandate editor rejects orders below 100 base tokens |
| `TICK_SPACING` is 10, ticks span `[-2000, 2000]`, `PRICE_SCALE` 100000 | `readContract` on the constants | 1 tick is 0.001% of price (0.1 bp). Valid ticks are multiples of 10, so 1 bp steps. Corridor maximum half-width is 2% |
| Supported TIP-20 USD tokens: PathUSD (`…0000`, the quote root), AlphaUSD (`…0001`), BetaUSD (`…0002`), ThetaUSD (`…0003`), all 6 decimals, quote token PathUSD | `token.getMetadata` | Supported-pair list is read from chain, not hard-coded fiction |
| Books are discoverable by index via `bookKeyForIndex(i)` + `books(key)` | probe script, 12+ books on Moderato | Markets screen enumerates real books |
| ABI includes `OrderFlipped(orderId, …)` and `FlipFailed(orderId, maker, reason)` | `Abis.stablecoinDex` in viem 2.57.4, chain definition `hardfork: 't5'` | TIP-1056 same-ID flip semantics are the modelled behaviour. Live flip still has to be observed, see `LIVE_RUN.md` |
| Placing a bid escrows `amount × price` of the quote token immediately (100 BetaUSD at 0.9997 moved 99.97 PathUSD out of the wallet) | wallet balance delta in run `2026-10-12T00-53-02-103Z` | Committed inventory is read from chain, not inferred |
| **Cancel refunds escrow to the DEX internal balance, not the wallet.** After cancel, wallet PathUSD did not come back, `dex.balanceOf` showed 99.97 PathUSD | same run | "Cancel live orders" and "Withdraw to wallet" are separate steps in the product. The UI must never claim cancellation returned funds to the wallet |
| No token approval was needed before `placeFlip` | placement succeeded from a fresh faucet-funded account | Review step lists no approval transaction |
| Fees are paid in a TIP-20 fee token (`feeToken: PathUSD`), about 0.0002 PathUSD per DEX transaction | wallet delta between place and cancel | Review step shows fee token and an upper bound, not a fiat gas number |
| Receipt inclusion took about 1.0 s after submission on both place and cancel | step timings in the run record | Staged UI copy "Submitted → Included → Verifying" has to be honest at that speed. No artificial delay is added |
| `getTickLevel` fails on many levels: out of gas against the 50M call cap, or an HTML gateway error, mostly for levels behind the touch. Populated near-touch levels read in about 250 ms | sequential scan of BetaUSD ticks −60…60 | Depth ladder marks those ticks "unreadable" instead of drawing zero. Executable depth is cross-checked with `quoteSwapExactAmountIn` |
| Public RPC rate-limits parallel bursts (`rate limited, try again`) | parallel 42-call scan | Server reads are sequential with a short cache, so browsers never fan out against the RPC |
| `quoteSwapExactAmountIn` is fast (about 270 ms) and works at sizes up to 50M | quote sweep on BetaUSD/PathUSD | Used as the "executable now" cross-check |
| Faucet RPC method `tempo_fundAddress` mints 1,000,000 of each USD test token per call | `Actions.faucet.fund` | Judge path can fund a fresh testnet account without any personal wallet |
| `eth_getLogs` with an OR-list on topic1 (several order IDs) returns `Request exceeds defined limit` or an empty array, while the same query for one order ID returns the full lifecycle | raw RPC call plus `/api/events` | Korrin scans each tracked order's topic separately, at most 3 at a time, with an 8 s cache |
| A book's `bestBidTick` can sit above its `bestAskTick` (AlphaUSD/PathUSD showed bid 1.0048, ask 1.0001), and `getTickLevel` at a reported best tick can return 0 liquidity | `books()` and `getTickLevel` reads | `place` rests orders without matching, so crossed books are a real state. The Markets screen labels them "crossed" and the planner checks crossing against the reported best ticks |
| `getTickLevel` gas grows with the number of orders resting at the level, because the precompile walks them. On BetaUSD, ask tick 10 needed about 21M gas (estimateGas), ask tick 40 about 7M, bid tick −10 about 0.8M, and bid tick −20 fails even at 49M. So "unreadable" means the level holds more orders than one call can sum under the RPC's 50M cap | reads at 3M, 10M, 25M and 49M gas caps plus `eth_estimateGas` | Level reads send `gas: 49_000_000`, which turns the heaviest levels into a fast, definite out-of-gas (about 400 ms) instead of a gateway HTML error. The corridor labels those ticks unreadable instead of drawing them empty |
| JSON-RPC batch requests (an array body) come back in a shape viem cannot parse, so every item fails | 32-call batch test | Korrin sends level reads as individual calls, six at a time |
